# Domain: Legal

## Dataset

[`dvgodoy/CUAD_v1_Contract_Understanding_clause_classification`](https://huggingface.co/datasets/dvgodoy/CUAD_v1_Contract_Understanding_clause_classification) — 13,155 rows, CC-BY-4.0.


Field names were verified against the real dataset before this config was written, not assumed.

## Task

Contract clause → CUAD clause type. Framed as instruction-following via `input_template`, since the raw data is a classification set rather than instructions.

## Pipeline

```bash
make data DOMAIN=legal
```

Download → exact + near-duplicate dedup → decontaminate against mmlu → hold out 500 unseen examples. Runs locally, no GPU. Stats land in `results/`.

Then run `notebooks/quickstart_colab.ipynb` (already set to `DOMAIN = "legal"`) on a Colab GPU: baseline eval → train → identical eval → report.

## Eval

**Primary:** Exact-match accuracy on held-out clause labels — objective, because the target is a discrete class rather than free text.

Evals run for this domain:

- `holdout`: held-out split
- `mcq`: mmlu

MMLU is the general-capability regression check every domain runs — it catches a finetune that buys domain skill by degrading everything else.

## Results

`results/report.md`, generated by `python -m src.eval.report --domain legal`. Populated after a real Colab run — not before.

## Known limitations

- Clause-type classification is a narrow slice of legal work. It is not drafting, advice, or review, and a gain here does not generalize to those.
- Chosen deliberately over synthetic 'legal advice' instruction sets: those have no objective metric, and unverifiable legal text is the worst thing to score on vibes. CUAD is a real, peer-reviewed corpus (the Atticus Project) with a measurable target.
- Exact-match is strict — a correct clause type phrased differently scores as wrong, so absolute accuracy understates real performance. The baseline-vs-finetuned comparison is still fair, since both sides are scored identically.
- **Not legal advice.** Public contract data, benchmark use only.
