# Domain: Code

## Dataset

[`glaiveai/glaive-code-assistant-v3`](https://huggingface.co/datasets/glaiveai/glaive-code-assistant-v3) — 950,384 rows, Apache-2.0.


Field names were verified against the real dataset before this config was written, not assumed.

## Task

Instruction → code answer. Synthetic coding Q&A pairs across many languages.

## Pipeline

```bash
make data DOMAIN=code
```

Download → exact + near-duplicate dedup → decontaminate against openai_humaneval, mbpp, mmlu → hold out 500 unseen examples. Runs locally, no GPU. Stats land in `results/`.

Then run `notebooks/quickstart_colab.ipynb` (already set to `DOMAIN = "code"`) on a Colab GPU: baseline eval → train → identical eval → report.

## Eval

**Primary:** HumanEval+ / MBPP+ pass@1 — execution-based: generated code is run against real test suites.

Evals run for this domain:

- `code`: humaneval
- `code`: mbpp
- `mcq`: mmlu
- `holdout`: held-out split

MMLU is the general-capability regression check every domain runs — it catches a finetune that buys domain skill by degrading everything else.

## Results

`results/report.md`, generated by `python -m src.eval.report --domain code`. Populated after a real Colab run — not before.

## Known limitations

- 20k-row subsample of a 950k-row dataset, 1 epoch, rank-16 LoRA. A resource-constrained run, not a full training budget.
- HumanEval+/MBPP+ measure isolated function generation. They say nothing about repo-level work — reading an existing codebase, multi-file edits, tool use. That is SWE-bench territory and is deliberately out of scope (see `docs/ARCHITECTURE.md`).
- The dataset is synthetic. A production code finetune would train on the organization's own repos and review history, which is exactly the data that isn't public.
