A hands-on guide to agent memory

Agent Memory Lab

On Monday you tell an AI assistant you're vegetarian. On Friday you ask where to eat, and it suggests a steakhouse. It didn't forget. It never remembered in the first place.

What's actually going on

A language model has no memory of its own. Every time you send a message, the app hands the model one block of text, called the context window, and the model answers using only what's in that block. When the chat grows too long to fit, the oldest messages fall off the end. Close the chat, and the whole block is gone.

So when people say an agent "has memory", they mean the software around the model is doing three jobs: deciding what's worth writing down, storing it somewhere outside the model, and pasting the right pieces back into the context window at the right moment. The model itself never changes.

Agentic memory goes one step further. The agent decides for itself what to save, update, or forget, usually by calling memory tools (like save_fact or search_memory) the same way it calls any other tool. The playground below runs that loop with nothing hidden.

Researchers usually split agent memory into four kinds, borrowed from human psychology. The split most people cite comes from the CoALA paper. Here they are, using the same vegetarian example all the way through.

Working memory

What the model can see right now

In our example
The last few messages of today's chat.
Like a human
Holding a phone number in your head while you dial it.
Catch
Small, and wiped when the session ends. This is the only memory the model reads directly.
Episodic memory

Things that happened, and when

In our example
Session 1: you said the ramen place was closed.
Like a human
Remembering the dinner where the waiter spilled wine.
Stored as
A time-stamped log of events, searched by similarity to the new message.
Semantic memory

Facts, with the "when" stripped away

In our example
Diet: vegetarian. Home: Lisbon.
Like a human
Knowing Lisbon is in Portugal without recalling where you learned it.
Stored as
A profile of key/value facts, database rows, or embedded text snippets.
Procedural memory

How to behave

In our example
Always keep answers short, in bullet points.
Like a human
Riding a bike. You don't recall it, you just do it.
Stored as
System prompt text, instruction files, or saved tools and skills. Usually loaded every time.

What the model receives

One message, five steps

Every time you hit Send in the playground, this runs in order. Real systems add embeddings, databases, and a real model, but the shape is the same.

  1. 1

    Retrieve

    Search the long-term stores using the new message. "Dinner" pulls up your diet and your city.

  2. 2

    Assemble

    Build the prompt: rules first, then recalled facts and events, then recent chat, then your message.

  3. 3

    Respond

    The model answers. It only knows what made it into that prompt.

  4. 4

    Write

    Pull out anything worth keeping: a new fact, a new rule, a notable event.

  5. 5

    Maintain

    Resolve conflicts (Lisbon becomes Berlin), merge duplicates, and forget what's stale.

The hard parts

What to write down

Save everything and retrieval drowns in noise. Save too little and the agent misses the one fact that mattered. "I'm vegetarian" is worth keeping. "lol ok" is not.

Conflicts

You lived in Lisbon, now you live in Berlin. The store has to replace the old fact, not keep both and pick one at random.

Retrieval misses

Ask "what should I cook?" and a keyword search may not connect it to "vegetarian". Real systems use embeddings for this, and they still miss sometimes.

Staleness

A budget from two years ago is probably wrong now. Good systems let memories fade or ask to confirm old ones.

Memory poisoning

If an agent saves text from a web page as a rule, that page now steers every future session. Stored memory should be treated as data, not as instructions.

Privacy

People forget what they told an assistant. Users need to see, edit, and delete what's stored, like the × buttons above.

Where you've already met this

Claude Code, the tool that built this page, keeps a memory folder per project: one small Markdown file per fact, plus an index file called MEMORY.md that is loaded at the start of every session. That's semantic and procedural memory stored as plain files, and the agent writes to it itself, which makes it agentic memory.

MemGPT (now the Letta project) treats the context window like a computer's RAM and outside storage like its disk, and lets the model move information between them with function calls. Mem0 is a memory layer that pulls facts out of conversations and updates or deletes them when new information conflicts.
