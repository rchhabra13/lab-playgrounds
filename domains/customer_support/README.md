# Domain: Customer Support

## Dataset

[`bitext/Bitext-customer-support-llm-chatbot-training-dataset`](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset) — 26,872 rows, CDLA-Sharing-1.0.


Field names were verified against the real dataset before this config was written, not assumed.

## Task

Customer request → support response. Covers order, refund, account, and shipping intents.

## Pipeline

```bash
make data DOMAIN=customer_support
```

Download → exact + near-duplicate dedup → decontaminate against mmlu → hold out 500 unseen examples. Runs locally, no GPU. Stats land in `results/`.

Then run `notebooks/quickstart_colab.ipynb` (already set to `DOMAIN = "customer_support"`) on a Colab GPU: baseline eval → train → identical eval → report.

## Eval

**Primary:** Held-out perplexity, plus the MMLU regression check.

Evals run for this domain:

- `holdout`: held-out split
- `mcq`: mmlu

MMLU is the general-capability regression check every domain runs — it catches a finetune that buys domain skill by degrading everything else.

## Results

`results/report.md`, generated by `python -m src.eval.report --domain customer_support`. Populated after a real Colab run — not before.

## Known limitations

- **No objective benchmark.** Support replies are free text with no single right answer, so perplexity is the primary number and it only shows distribution fit.
- The dataset carries `intent` and `category` labels, and intent-classification accuracy was considered as an eval. It was rejected: the model is trained to write responses, not emit intent labels, so scoring it on intents would measure a task it was never trained for.
- Responses contain templated placeholders like `{{Order Number}}`. The model will learn to reproduce them — realistic for a templated support bot, but it means outputs are not directly user-facing without substitution.
- 20k-row subsample, 1 epoch, rank-16 LoRA.
