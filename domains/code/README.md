# Domain: Code

## Dataset

[`glaiveai/glaive-code-assistant-v3`](https://huggingface.co/datasets/glaiveai/glaive-code-assistant-v3) — 950,384 synthetic instruction/code Q&A pairs, Apache-2.0. Fields: `question`, `answer`.

Capped to the first 20,000 rows (`domains/code/data_config.yaml: max_examples`) so a full data-prep → train → eval cycle fits a free-tier Colab T4 session. Raise or drop that cap if you have more GPU budget.

## Pipeline

1. `make data DOMAIN=code` — download → exact hash dedup → MinHash near-dup dedup → decontaminate against HumanEval/MBPP. Runs locally, no GPU. Stats written to `results/dedup_stats.json` and `results/decontamination_stats.json`.
2. `notebooks/quickstart_colab.ipynb` (`DOMAIN = "code"`) — Unsloth LoRA SFT of Qwen3-8B-Instruct on Colab. Baseline eval → train → finetuned eval, same harness both times.

## Eval

[HumanEval+ / MBPP+](https://github.com/evalplus/evalplus), execution-based pass@1. Not SWE-bench — this measures isolated function-generation correctness, not repo-level issue resolution. See `docs/ARCHITECTURE.md` for why.

## Results

See `results/report.md` (generated by `python -m src.eval.report --domain code`) and the cross-domain table in `docs/RESULTS.md`. Populated after a real Colab run — not before.

## Known limitations

- 20k-row subsample of a 950k-row dataset, 1 epoch, rank-16 LoRA — a resource-constrained run, not a from-scratch training budget.
- No RL/DPO stage yet. `src/monitor/log_feedback.py` exists to start collecting accept/reject signal for a future DPO pass, but there's no live traffic generating that signal here.
- HumanEval+/MBPP+ scores general code-generation correctness, not this repo's actual "business domain" use case (e.g. repo-aware review, internal API idioms) — a real production fine-tune would eval against internal code and internal review data, which isn't public and isn't included here.
